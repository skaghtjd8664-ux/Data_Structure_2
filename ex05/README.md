# 과제-05: 순차 탐색과 이진 탐색 트리(BST) 탐색의 비교

## 1. 순차 탐색와 BST 탐색의 총 및 평균 비교 횟수

```
Sequential Search
  Total comparisons   : 4542
  Average comparisons : 90.84

BST Search
  Total comparisons   : 391
  Average comparisons : 7.82
```

## 2. BST를 생성하는 과정에서 발생한 비교 횟수

```
- BST 생성 중 총 비교 횟수 : 594
- 생성된 BST의 높이        : 11
```

## 3. 순차 탐색 방법과 BST 탐색 방법의 성능 차이에 대한 분석

### 3-1 순차 탐색 방법

**순차 탐색**은 비교 1회당 "이 값은 아니다"라는 정보만 얻을 뿐 나머지 탐색 범위는 전혀 줄어들지 않는다.

그래서 n개 중 찾는 값이 없으면 반드시 n개 비교해야 하고, 평균적으로도 n에 가까운 비교가 필요하다.

즉 비교 횟수가 n에 **비례(O(n))**한다.

### 3-2 BST 탐색 방법

**BST 탐색**은 비교 1회마다 왼쪽인지 오른쪽인지가 결정되면서 남은 탐색 범위가 대략 절반으로 줄어든다. 그래서 n개의 노드가 균형 잡혀 있다면 최대 log₂n 번 정도의 비교로 끝난다. 즉 비교 횟수가 **O(log n)**으로 늘어난다.

### 3-3 두 방법의 성능 차이에 대한 분석

BST가 탐색 과정에서 현재 노드를 기준으로 탐색해야 할 방향을 결정하기 때문에 불필요한 데이터를 모두 확인하지 않아도 되기 때문이다.

데이터의 크기가 커질수록 순차 탐색은 데이터 개수에 비례하여 비교 횟수가 증가하지만, 균형에 가까운 BST는 비교 횟수가 로그 형태로 증가한다.

따라서 데이터의 양이 많아질수록 두 탐색 방법의 성능 차이가 더욱 커질 수 있다.

## 4. BST 생성 비용을 고려했을 때의 성능 차이에 대한 분석

``` 
BST 생성 비용 (총 비교 횟수) : 594
BST 탐색 50회 총 비교 횟수   : 391
BST 생성+탐색 합계           : 985
순차 탐색 50회 총 비교 횟수   : 4542
```

따라서 BST 생성 비용까지 포함하더라도 이번 실험에서는 BST를 이용하는 방법이 순차 탐색보다 약 4.6배 적은 비교 횟수를 사용하였다.

즉, 탐색을 여러 번 수행하는 상황에서는 BST를 생성하는 초기 비용이 있더라도 이후 탐색에서 절약되는 비교 횟수가 커지기 때문에 전체적인 성능에서 유리할 수 있다.

특히 탐색 횟수가 많아질수록 BST 생성 비용을 여러 번의 빠른 탐색으로 분산시킬 수 있기 때문에 BST의 장점이 더욱 커진다.

## 5. 이진 탐색 트리의 구조에 따라 탐색 성능이 어떻게 달라질 수 있는지에 대한 분석

100개의 노드로 구성된 이진 트리에서 노드가 최대한 균형 있게 배치된다면 필요한 최소 높이는 약 7 수준이다. 하지만 이번 실험에서는 입력된 값이 무작위 순서로 삽입되었기 때문에 완전히 균형 잡힌 트리가 만들어지지는 않았다.

이번 실험의 BST 높이는 11로, 무작위 삽입 과정에서 일부 경로가 다른 경로보다 길어졌음을 확인할 수 있다.

BST의 탐색 성능은 트리의 구조에 큰 영향을 받는다.

### 5-1 편향 이진트리인 경우

100개의 정수가 이미 정렬된 순서(1, 2, 3, …, 100)로 삽입된다면, 각 노드는 이전 노드의 한쪽 자식으로만 계속 연결되어 트리가 사실상 "한 방향으로 뻗은 연결리스트"가 되어버린다. 이 경우 높이가 n에비례하게 되어 BST 탐색도 순차 탐색과 똑같이 O(n)이 되고, BST를 쓰는 의미가 사라진다.

### 5-2 균형 이진 트리인 경우

노드가 균형 있게 분포되어 있다면 한 번의 비교를 통해 탐색해야 할 영역을 크게 줄일 수 있다. 이 경우 트리의 높이가 약 log₂n 수준이 되므로 탐색 성능도 평균적으로 O(log n)에 가까워진다. 100개의 노드가 최대한 균형 있게 구성된 경우 높이는 약 7 수준까지 줄일 수 있다.

## 6. 결론

100개의 정수를 이용하여 BST를 생성하고, 50개의 탐색 대상에 대해 순차 탐색과 BST 탐색의 성능을 비교했을 때 실험 결과 순차 탐색은 총 4542회의 비교와 평균 90.84회의 비교가 발생한 반면, BST 탐색은 총 391회의 비교와 평균 7.82회의 비교만 발생하였다.

또한 BST를 생성하는 과정에서 발생한 594회의 비교를 포함하더라도 전체 비교 횟수는 985회로, 순차 탐색의 4542회보다 적었다. 따라서 이번 실험에서는 BST 생성 비용을 고려하더라도 BST 탐색이 더 효율적인 결과를 보여주었다.

하지만 BST의 성능은 트리의 구조와 데이터가 삽입되는 순서에 영향을 받는다. 균형이 잘 잡힌 경우 O(log n)의 효율적인 탐색이 가능하지만, 데이터가 한쪽으로 치우쳐 트리가 편향되면 최악의 경우 O(n)까지 성능이 저하될 수 있다.

따라서 많은 데이터를 대상으로 탐색을 반복해야 하는 경우 BST를 사용하는 것이 순차 탐색보다 유리하며, 안정적으로 균형을 유지해야 하는 상황에서는 BST 탐색을 사용하는 것이 더 효율적이다.
