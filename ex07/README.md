# 과제 07: 인접 행렬과 인접 리스트의 성능 비교

## 1. 실험 목적

정점이 100개인 무방향 단순 그래프를 대상으로 인접 행렬과 인접 리스트를 각각 구현하고, 희소 그래프와 밀집 그래프에서 두 표현 방식의 메모리 사용량 및 연산 비교 횟수를 측정하였다.

실험 대상은 다음과 같다.

- 희소 그래프: 정점 100개, 간선 100개
- 밀집 그래프: 정점 100개, 간선 4,000개
- 인접 행렬: `matrix[100][100]`
- 인접 리스트: 정점별 연결 리스트

각 그래프는 먼저 하나의 인접 행렬로 생성한 뒤, 같은 행렬을 이용하여 인접 리스트를 구성하였다. 따라서 인접 행렬과 인접 리스트는 표현 방법만 다르고 동일한 그래프를 사용한다.

---

## 2. 비교 횟수의 기준

이번 프로그램에서는 그래프 자료구조의 원소 또는 간선 정보를 실제로 확인한 횟수를 비교 횟수로 계산하였다.

- 인접 행렬에서 간선 삽입, 삭제, 연결 여부 확인: 해당 행렬 원소를 확인할 때 1회
- 인접 리스트에서 간선 삽입, 삭제, 연결 여부 확인: 리스트 노드를 하나씩 확인한 횟수
- 특정 정점의 인접 정점 출력
  - 인접 행렬: 해당 행의 100개 원소 확인
  - 인접 리스트: 해당 정점의 리스트 노드 수만큼 확인

무방향 그래프이므로 하나의 간선은 양쪽 정점의 자료구조에 모두 저장하였다. 인접 리스트에서 간선 삭제는 양쪽 리스트에서 해당 노드를 찾아 제거하므로 양쪽 검색에서 확인한 노드 수를 합산하였다.

---

## 3. 메모리 계산 방법

### 인접 행렬

인접 행렬은 100 × 100개의 `int`를 사용한다.

```text
100 × 100 × sizeof(int)
= 10000 × 4
= 40,000 Bytes
```

따라서 그래프의 간선 수와 관계없이 인접 행렬은 항상 약 40,000바이트를 사용한다. 실제 실행 환경에서 `sizeof(int)`의 크기가 4바이트라는 전제에 따른 값이다.

### 인접 리스트

인접 리스트는 정점별 head 포인터 배열과 간선 노드로 구성된다.

```text
인접 리스트 메모리
= sizeof(AdjList)
  + 저장된 인접 노드 개수 × sizeof(AdjNode)
```

무방향 그래프에서 간선 하나는 두 개의 인접 리스트 노드로 저장되므로, 간선이 `E`개이면 인접 노드 수는 `2E`개이다.

따라서 인접 리스트의 메모리는 다음과 같이 증가한다.

```text
희소 그래프: sizeof(AdjList) + 200 × sizeof(AdjNode)
밀집 그래프: sizeof(AdjList) + 8000 × sizeof(AdjNode)
```

인접 리스트의 정확한 메모리 값은 포인터 크기와 구조체 패딩에 따라 달라질 수 있으므로 프로그램에서 `sizeof`를 이용해 직접 계산하였다.

## 4. 실행 결과 기록

프로그램을 실행할 때마다 난수가 달라지므로 간선 삽입 및 삭제, 연결 여부 확인 비교 횟수는 달라질 수 있다. 아래 값은 프로그램의 한 실행 결과 예시이다.

> 제출할 때는 본인이 실행한 최종 결과로 아래 표의 값을 교체하는 것이 좋다.

| 구분 | 메모리 | 삽입 비교 | 삭제 비교 | 연결 확인 비교 | 인접 정점 출력 비교 |
|---|---:|---:|---:|---:|---:|
| 희소-인접 행렬 | 40,000 Bytes | 1 | 1 | 1 | 100 |
| 희소-인접 리스트 | 4,000 Bytes | 3 | 7 | 3 | 3 |
| 밀집-인접 행렬 | 40,000 Bytes | 1 | 1 | 1 | 100 |
| 밀집-인접 리스트 | 128,800 Bytes | 79 | 159 | 2 | 79 |

위의 리스트 삭제 비교 횟수는 양쪽 인접 리스트에서 간선을 찾는 비교 횟수를 합산하는 현재 코드 기준이다. 난수 그래프와 선택된 간선에 따라 값은 달라진다.

## 5. 희소 그래프 분석

희소 그래프는 정점 100개에 간선 100개만 존재하므로 전체 가능한 간선 수에 비해 실제 간선 수가 적다.

인접 행렬은 희소 그래프에서도 100 × 100개의 공간을 모두 사용한다. 따라서 메모리 사용량은 40,000바이트로 고정된다. 간선이 적더라도 연결되지 않은 간선을 표현하기 위한 0 값 저장 공간이 필요하다.

반면 인접 리스트는 실제로 존재하는 간선만 저장한다. 무방향 간선 100개는 리스트 노드 200개로 저장되므로 인접 행렬보다 훨씬 적은 메모리를 사용한다. 예시 실행에서도 인접 리스트는 4,000바이트로, 인접 행렬의 40,000바이트보다 작았다.

간선 삽입과 삭제에서도 차이가 나타난다. 인접 행렬은 특정 위치를 바로 확인할 수 있기 때문에 비교 횟수가 항상 1회이다. 인접 리스트는 해당 정점의 리스트를 처음부터 검색해야 하므로 리스트의 길이와 간선의 위치에 따라 비교 횟수가 달라진다.

특정 정점의 인접 정점을 출력할 때 인접 행렬은 연결된 간선이 몇 개뿐이어도 해당 행의 100개 원소를 모두 확인해야 한다. 반면 인접 리스트는 실제 인접 정점만 확인하면 되므로 희소 그래프에서는 일반적으로 더 적은 비교가 발생한다.

따라서 희소 그래프에서는 메모리와 인접 정점 순회 측면에서 인접 리스트가 유리하다. 다만 특정 두 정점의 연결 여부를 매우 자주 확인해야 한다면 인접 행렬의 일정한 1회 확인이 유리할 수 있다.

---

## 6. 밀집 그래프 분석

밀집 그래프는 정점 100개에 간선 4,000개가 존재한다. 가능한 무방향 단순 간선의 최대 개수는 다음과 같다.

```text
100 × 99 / 2 = 4,950개
```

따라서 4,000개의 간선을 가진 그래프는 가능한 간선 대부분이 존재하는 밀집 그래프이다.

인접 행렬의 메모리는 희소 그래프와 마찬가지로 40,000바이트이다. 인접 행렬은 간선 수와 관계없이 항상 동일한 100 × 100 공간을 사용하기 때문이다.

인접 리스트는 4,000개의 간선을 양방향으로 저장하므로 8,000개의 리스트 노드가 필요하다. 따라서 밀집 그래프에서는 인접 리스트가 저장하는 노드 수가 크게 증가하고, 메모리 사용량이 인접 행렬보다 커질 수 있다. 예시 실행에서는 인접 리스트가 128,800바이트를 사용하여 인접 행렬보다 훨씬 컸다.

간선 삽입, 삭제, 연결 여부 확인에서도 밀집 그래프에서는 리스트의 검색 길이가 길어질 가능성이 커진다. 특히 어떤 정점의 인접 리스트가 매우 긴 경우, 특정 인접 정점을 찾기 위해 많은 노드를 확인해야 한다.

인접 정점 출력 비교에서는 인접 행렬이 항상 100회의 비교를 수행한다. 인접 리스트는 해당 정점의 차수만큼 비교하므로, 밀집 그래프에서는 차수가 크기 때문에 인접 행렬과 비슷하거나 더 많은 작업이 필요할 수 있다.

따라서 밀집 그래프에서는 메모리 사용량이 일정하고, 연결 여부 확인을 1회에 수행할 수 있는 인접 행렬이 더 적합하다.

## 7. 연산별 비교

### 간선 삽입

인접 행렬은 `matrix[u][v]`를 바로 확인하므로 비교 횟수가 1회이다. 이후 양방향 위치에 1을 저장한다.

인접 리스트는 정점 `u`의 리스트에서 `v`가 이미 존재하는지 확인해야 한다. 리스트 앞부분에서 발견되면 비교 횟수가 적지만, 뒤쪽에 있거나 존재하지 않으면 리스트를 많이 확인해야 한다.

### 간선 삭제

인접 행렬은 `matrix[u][v]`를 바로 확인한 뒤 0으로 변경하므로 비교 횟수가 1회이다.

인접 리스트는 `u`의 리스트에서 `v`를 찾고, 무방향 그래프의 반대쪽 리스트에서도 `u`를 찾아야 한다. 따라서 두 리스트의 검색 비용이 합산된다.

### 연결 여부 확인

인접 행렬은 어떤 정점 쌍이든 배열 위치를 바로 계산할 수 있어 항상 1회이다.

인접 리스트는 한쪽 정점의 인접 리스트를 순차적으로 확인한다. 연결된 정점이 리스트 뒤쪽에 있거나 연결되지 않은 경우 비교 횟수가 증가한다.

### 인접 정점 출력

인접 행렬은 해당 정점의 모든 가능한 정점에 대해 연결 여부를 확인하므로 정점 수인 100회가 필요하다.

인접 리스트는 실제로 저장된 인접 노드만 방문한다. 따라서 희소 그래프에서는 차수가 작아 인접 리스트가 유리하지만, 밀집 그래프에서는 차수가 커져 인접 행렬과의 차이가 줄어든다.

## 8. 어떤 표현을 사용해야 하는가

### 인접 행렬이 적합한 경우

- 그래프가 밀집되어 있는 경우
- 두 정점의 직접 연결 여부를 자주 확인하는 경우
- 간선 삽입과 삭제를 빠르게 처리해야 하는 경우
- 정점 수가 비교적 작고 메모리 사용량이 큰 문제가 되지 않는 경우

인접 행렬은 연결 여부 확인이 항상 1회이므로 간선 존재 여부를 빈번하게 검사하는 그래프 알고리즘에 적합하다.

### 인접 리스트가 적합한 경우

- 그래프가 희소한 경우
- 실제 간선의 수가 정점 수에 비해 적은 경우
- 특정 정점에서 연결된 정점들을 순회하는 작업이 많은 경우
- 메모리를 절약해야 하는 경우

인접 리스트는 존재하지 않는 간선을 위한 공간을 별도로 저장하지 않으므로 희소 그래프에서 매우 효율적이다.

---

## 9. 결론

이번 실험을 통해 그래프의 밀도에 따라 적합한 표현 방식이 달라진다는 것을 확인하였다.

희소 그래프에서는 인접 리스트가 실제 간선만 저장하기 때문에 인접 행렬보다 메모리를 적게 사용한다. 또한 특정 정점의 인접 정점을 출력할 때 실제 이웃만 확인하므로 비교 횟수도 적다.

반면 인접 행렬은 희소 그래프에서도 100 × 100 공간을 모두 사용하지만, 간선 삽입·삭제와 두 정점의 연결 여부 확인을 1회의 비교로 처리할 수 있다.

밀집 그래프에서는 인접 리스트에 많은 간선 노드가 저장되므로 메모리 사용량이 증가하고, 리스트 탐색 비용도 커진다. 이 경우에는 고정된 100 × 100 공간을 사용하면서 연결 여부를 일정한 시간에 확인할 수 있는 인접 행렬이 더 적합하다.

정리하면 다음과 같다.

```text
희소 그래프: 인접 리스트가 메모리와 인접 정점 순회에 유리
밀집 그래프: 인접 행렬이 메모리 예측과 연결 여부 확인에 유리
```

따라서 자료구조를 선택할 때는 단순히 하나의 표현 방식을 사용하는 것이 아니라, 그래프의 간선 밀도와 주로 수행할 연산을 함께 고려해야 한다.
