# 과제 06: 순차 탐색, BST, AVL 트리의 성능 비교

## 1. 실험 개요

본 과제에서는 0부터 1,000 사이의 정수 100개를 순서대로 생성한 뒤, 배열(Array), 이진 탐색 트리(Binary Search Tree, BST), AVL 트리에 저장하였다. 생성된 값 중 중복 값은 각 자료구조에서 확인한 후 삽입하지 않았다.

이후 50개의 탐색 키를 생성하여 동일한 키를 대상으로 다음 세 가지 탐색을 수행하였다.

- 배열: 순차 탐색(Sequential Search)
- BST: 이진 탐색 트리 탐색
- AVL: AVL 트리 탐색

각 자료구조의 생성 과정과 탐색 과정에서 발생한 숫자 비교 횟수를 측정하고, 생성된 트리의 높이 및 탐색 성능을 비교하였다.

---

## 2. 생성된 데이터와 저장 결과

총 100개의 난수를 생성하였다. 이 중 중복된 값은 5개였으며, 실제로 저장된 서로 다른 값은 95개였다.

| 항목 | 결과 |
|---|---:|
| 난수 생성 시도 횟수 | 100회 |
| 실제 저장된 서로 다른 값의 수 | 95개 |
| 중복으로 삽입되지 않은 값의 수 | 5개 |

생성된 값 중 중복된 값은 다음과 같다.

- 165
- 685
- 592
- 918
- 573

배열, BST, AVL은 동일한 난수를 동일한 순서로 처리했으므로 세 자료구조에 저장된 서로 다른 값의 수는 모두 95개이다.

---

## 3. 생성 과정의 비교 횟수

각 자료구조에 값을 삽입하는 과정에서 발생한 숫자 비교 횟수는 다음과 같다.

| 자료구조 | 생성 과정 비교 횟수 |
|---|---:|
| 배열 | 4,733회 |
| BST | 622회 |
| AVL | 535회 |

### 배열

배열은 새로운 값이 들어올 때마다 배열의 첫 번째 원소부터 현재 마지막 원소까지 순서대로 비교하여 중복 여부를 확인한다. 따라서 저장된 값의 수가 증가할수록 중복 확인에 필요한 비교 횟수도 증가한다.

이번 실험에서 배열의 생성 비교 횟수는 **4,733회**로 세 자료구조 중 가장 많았다. 배열은 값의 크기를 이용해 탐색 범위를 줄이지 못하고 모든 원소를 차례대로 확인하기 때문에 비교 횟수가 크게 발생하였다.

### BST

BST는 현재 노드의 값과 삽입할 값을 비교한 후, 삽입할 값이 작으면 왼쪽으로 이동하고 크면 오른쪽으로 이동한다. 따라서 배열처럼 모든 값을 확인하지 않고 트리의 한 경로만 따라간다.

BST의 생성 비교 횟수는 **622회**였다. 배열보다 훨씬 적은 비교로 삽입 위치 또는 중복 여부를 확인했지만, 삽입 순서에 따라 트리가 완전히 균형을 이루지 않을 수 있기 때문에 AVL보다 비교 횟수가 많았다.

### AVL

AVL은 BST의 탐색 규칙을 유지하면서 삽입 후 회전을 통해 트리의 균형을 유지한다. 이번 실험에서 AVL의 생성 비교 횟수는 **535회**로 가장 적었다.

AVL의 높이 계산, balance factor 계산 및 회전 작업은 과제의 조건에 따라 숫자 비교 횟수에 포함하지 않았다. 따라서 측정된 비교 횟수는 삽입 위치 또는 중복 여부를 확인하기 위해 삽입값과 노드의 값을 비교한 횟수이다.

---

## 4. 자료구조의 크기와 높이

모든 삽입 시도가 완료된 후의 구조는 다음과 같다.

| 자료구조 | 크기 또는 높이 |
|---|---:|
| 배열 길이 | 95 |
| BST 높이 | 12 |
| AVL 높이 | 8 |

배열에는 95개의 서로 다른 값이 저장되었다. BST와 AVL에도 동일하게 95개의 값이 저장되었다.

BST의 높이는 **12**, AVL의 높이는 **8**이었다. 두 트리에 저장된 데이터의 수는 같지만 트리의 구조가 다르기 때문에 높이 차이가 발생하였다.

BST는 입력 데이터의 삽입 순서에 따라 구조가 결정된다. 이번 실험에서는 값이 삽입되는 과정에서 트리가 완전히 균형 있게 구성되지 않았기 때문에 일부 경로가 상대적으로 길어졌고, 그 결과 높이가 12가 되었다.

반면 AVL은 삽입 후 균형 조건을 확인하고 필요한 경우 LL, RR, LR, RL 회전을 수행한다. 이 과정을 통해 왼쪽과 오른쪽 서브트리의 높이 차이를 제한하므로 BST보다 낮은 높이인 8을 유지할 수 있었다.

---

## 5. 탐색 결과

50개의 탐색 키에 대해 순차 탐색, BST 탐색, AVL 탐색을 수행하였다.

| 탐색 방법 | 총 비교 횟수 | 평균 비교 횟수 |
|---|---:|---:|
| 순차 탐색 | 4,444회 | 88.88회 |
| BST 탐색 | 414회 | 8.28회 |
| AVL 탐색 | 334회 | 6.68회 |

### 순차 탐색

순차 탐색은 배열의 첫 번째 원소부터 차례대로 탐색한다. 탐색 대상이 배열의 앞쪽에 있으면 비교 횟수가 적지만, 뒤쪽에 있거나 배열에 존재하지 않으면 배열의 거의 모든 원소를 비교해야 한다.

실험 결과, 존재하지 않는 탐색 키 대부분에 대해 95개의 원소를 모두 비교하였다. 그 결과 총 비교 횟수는 **4,444회**, 평균 비교 횟수는 **88.88회**로 나타났다.

### BST 탐색

BST 탐색은 현재 노드의 값과 탐색 대상의 크기를 비교하면서 왼쪽 또는 오른쪽 서브트리로 이동한다. 따라서 배열처럼 95개의 값을 모두 확인하지 않고 루트에서 특정 단말 노드까지의 경로에 있는 노드만 비교한다.

BST 탐색의 총 비교 횟수는 **414회**, 평균 비교 횟수는 **8.28회**였다. BST의 높이가 12였기 때문에 최악의 경우 최대 12개 정도의 노드를 비교할 수 있으며, 실제 탐색에서는 탐색 대상의 위치에 따라 비교 횟수가 달라졌다.

### AVL 탐색

AVL 탐색 방법은 BST 탐색과 같지만 AVL 트리는 삽입 과정에서 균형을 유지한다. 그 결과 BST보다 트리의 높이가 낮고, 탐색 경로도 대체로 짧아진다.

AVL 탐색의 총 비교 횟수는 **334회**, 평균 비교 횟수는 **6.68회**였다. 이는 BST보다 총 80회 적은 비교이며, 평균적으로도 한 번의 탐색마다 1.60회 적은 비교를 수행한 것이다.

---

## 6. 탐색 비교 횟수에 대한 세부 분석

이번 실험에서는 탐색 키가 자료구조에 존재하는 경우와 존재하지 않는 경우가 모두 포함되었다.

탐색 결과를 보면 다음과 같은 특징을 확인할 수 있다.

1. 배열에서 존재하지 않는 값은 대부분 95회의 비교가 발생하였다.
2. BST와 AVL은 존재하지 않는 값이라도 트리의 높이만큼만 비교한 후 탐색을 종료하였다.
3. AVL은 BST보다 높이가 낮았기 때문에 대부분의 탐색에서 더 적은 비교 횟수를 보였다.
4. 특정 탐색 키에서는 BST가 AVL보다 적은 비교를 하는 경우도 있었지만, 전체 합계와 평균에서는 AVL이 더 우수했다.

예를 들어 탐색 키 776에 대해서는 다음과 같은 결과가 나타났다.

| 탐색 방법 | 비교 횟수 | 결과 |
|---|---:|---|
| 순차 탐색 | 58회 | Found |
| BST 탐색 | 9회 | Found |
| AVL 탐색 | 7회 | Found |

이 결과는 트리 구조를 이용하는 탐색이 배열의 순차 탐색보다 훨씬 효율적이라는 것을 보여준다.

다만 모든 개별 탐색에서 AVL이 반드시 BST보다 적은 비교를 하는 것은 아니다. 특정 값은 BST의 루트에 더 가까울 수 있기 때문이다. 그러나 여러 탐색을 종합하면 AVL은 균형을 유지하기 때문에 평균적인 탐색 성능이 더 안정적이다.

---

## 7. 생성 비용과 탐색 비용의 종합 비교

생성 비용과 50회 탐색 비용을 합산한 결과는 다음과 같다.

| 자료구조 | 생성 비교 | 탐색 비교 | 전체 비교 |
|---|---:|---:|---:|
| 배열 | 4,733회 | 4,444회 | 9,177회 |
| BST | 622회 | 414회 | 1,036회 |
| AVL | 535회 | 334회 | 869회 |

배열은 생성 과정에서 4,733회, 탐색 과정에서 4,444회의 비교를 수행하여 전체 9,177회의 비교가 발생하였다. 이는 세 자료구조 중 가장 높은 비용이다.

BST는 배열보다 훨씬 적은 1,036회의 전체 비교가 발생하였다. 트리의 구조를 이용하여 삽입과 탐색 시 불필요한 원소를 건너뛸 수 있었기 때문이다.

AVL은 생성과 탐색을 합하여 869회의 비교가 발생하였다. BST보다 전체 167회 적은 비교이며, 특히 탐색 과정에서 AVL의 장점이 뚜렷하게 나타났다.

---

## 8. 성능 비교 및 분석

### 배열의 장점과 단점

배열은 구현이 단순하고 데이터의 저장 순서를 그대로 유지할 수 있다는 장점이 있다. 또한 별도의 포인터나 회전 연산이 필요하지 않다.

하지만 중복 확인과 탐색 모두 처음부터 원소를 순서대로 확인해야 한다. 따라서 저장된 데이터가 많아질수록 비교 횟수가 크게 증가한다. 이번 실험에서도 배열의 전체 비교 횟수는 9,177회로 가장 많았다.

### BST의 장점과 단점

BST는 데이터의 크기 관계를 이용하여 탐색 범위를 줄이므로 배열보다 효율적이다. 이번 실험에서 BST의 생성 비교 횟수는 622회, 탐색 비교 횟수는 414회로 배열보다 크게 낮았다.

그러나 BST는 삽입 순서에 따라 트리의 구조가 달라진다. 특정 순서로 값이 삽입되면 한쪽으로 치우친 트리가 만들어질 수 있고, 이 경우 높이가 커져 탐색 성능이 저하될 수 있다.

### AVL의 장점과 단점

AVL은 삽입 시 회전을 수행하여 트리의 균형을 유지한다. 이번 실험에서 AVL의 높이는 8로 BST의 높이 12보다 낮았다. 그 결과 AVL의 탐색 총 비교 횟수는 334회로 BST의 414회보다 적었다.

AVL은 균형을 유지하기 위한 높이 계산과 회전 작업이 필요하다는 단점이 있다. 하지만 본 과제에서는 이러한 균형 유지 작업을 숫자 비교 횟수에 포함하지 않았으며, 실제 삽입 위치를 찾는 비교와 탐색 비교에서는 AVL이 가장 좋은 결과를 보였다.

## 9. 결론

이번 실험 결과를 통해 다음과 같은 결론을 얻을 수 있었다.

1. 배열은 구현이 가장 단순하지만 중복 확인과 탐색에 많은 비교가 필요하다.
2. BST는 배열보다 훨씬 적은 비교로 삽입과 탐색을 수행할 수 있다.
3. BST의 성능은 삽입 순서와 트리 높이에 영향을 받는다.
4. AVL은 회전을 통해 균형을 유지하므로 BST보다 낮은 높이를 유지할 수 있다.
5. 이번 실험에서는 AVL의 높이가 8, BST의 높이가 12로 나타났다.
6. AVL의 탐색 평균 비교 횟수는 6.68회로 BST의 8.28회보다 낮았다.
7. 생성과 탐색을 모두 고려한 전체 비교 횟수에서도 AVL이 869회로 가장 적었다.

따라서 탐색이 반복적으로 수행되고 데이터의 삽입 순서에 따라 트리의 균형이 무너질 가능성이 있는 경우에는 AVL 트리가 가장 안정적인 성능을 제공한다. 반면 데이터의 수가 작거나 구현의 단순성이 중요한 경우에는 배열 또는 일반 BST를 사용할 수 있다.

이번 실험에서는 전체 비교 횟수 기준으로 다음과 같은 성능 순서가 나타났다.

```text
AVL 트리 < BST < 배열
```

즉, 본 실험 조건에서는 AVL 트리가 생성과 탐색을 종합했을 때 가장 효율적인 자료구조였다.
