# 과제 10: 정렬 알고리즘의 성능 및 안정성 비교

## 1. 실험 개요

정수 키 2개(`key1`, `key2`)로 구성된 데이터 10,000개를 생성하고, 첫 번째 키인 `key1`을 기준으로 선택 정렬, 버블 정렬, 삽입 정렬의 성능을 비교하였다.

각 데이터에는 원래 입력 위치를 나타내는 `original_index`를 추가로 저장하였다. 이 값은 정렬 기준으로 사용하지 않고, `key1`이 같은 데이터의 상대적 순서가 유지되는지 확인하는 안정성 검증에만 사용하였다.

측정 항목은 다음과 같다.

- 숫자 비교 횟수: 두 데이터의 `key1`을 실제로 비교한 횟수
- 데이터 이동 횟수: 데이터 구조체 전체가 대입 또는 복사된 횟수
- 정렬 결과의 오름차순 여부
- 버블 정렬 조기 종료에 따른 비교 횟수 변화
- 입력 상태에 따른 알고리즘 성능 변화
- 각 정렬 알고리즘의 안정성

## 2. 구현한 정렬 알고리즘

### 선택 정렬

각 위치마다 정렬되지 않은 구간에서 `key1`이 가장 작은 데이터의 위치를 찾은 다음, 현재 위치의 데이터와 교환하였다. 선택 정렬은 입력 상태와 관계없이 비교 횟수가 거의 일정하며, 일반적으로 `O(n^2)`의 시간 복잡도를 가진다.

### 버블 정렬

서로 이웃한 두 데이터의 `key1`을 비교하여 앞의 값이 더 크면 교환하였다. 일반 버블 정렬은 입력이 이미 정렬되어 있어도 정해진 모든 순회를 수행하도록 구현하였다.

조기 종료 버블 정렬은 한 번의 순회에서 교환이 한 번도 발생하지 않으면 정렬이 완료된 것으로 판단하고 즉시 종료하였다.

### 삽입 정렬

현재 데이터를 임시 변수에 저장한 뒤, 정렬된 앞부분에서 더 큰 데이터를 오른쪽으로 이동시키고 현재 데이터를 빈 위치에 삽입하였다. 삽입 정렬은 이미 정렬된 데이터 또는 일부 정렬된 데이터에서 비교와 이동 횟수가 크게 줄어드는 특징이 있다.

## 3. 비교 및 이동 횟수 계산 기준

### 비교 횟수

정렬 순서를 결정하기 위해 다음과 같이 두 데이터의 `key1`을 비교할 때만 비교 횟수를 증가시켰다.

```c
if (a[i].key1 > a[j].key1)
```

반복문의 인덱스 조건이나 조기 종료 조건 자체의 판단은 숫자 비교 횟수에 포함하지 않았다.

### 데이터 이동 횟수

데이터 구조체 전체의 대입을 1회 이동으로 계산하였다. 선택 정렬과 버블 정렬에서 교환은 다음과 같이 3회의 이동으로 계산하였다.

```text
temp = a[i]  : 1회
a[i] = a[j]  : 1회
a[j] = temp  : 1회
```

삽입 정렬에서는 현재 데이터를 임시 변수에 저장하는 대입, 더 큰 데이터를 한 칸 오른쪽으로 이동하는 대입, 현재 데이터를 최종 위치에 저장하는 대입을 각각 1회로 계산하였다.

원본 배열을 알고리즘별 복사본으로 준비하는 과정과 시험 데이터 생성 과정은 이동 횟수에 포함하지 않았다.

## 4. 무작위 데이터 100회 실험

매 반복마다 새로운 무작위 데이터 10,000개를 생성하고, 동일한 원본 배열의 복사본을 네 가지 정렬에 제공하였다.

- 선택 정렬
- 일반 버블 정렬
- 조기 종료 버블 정렬
- 삽입 정렬

각 반복의 정렬 결과가 `key1` 기준 오름차순인지 검사하였다. 모든 알고리즘이 같은 입력을 사용하므로 결과 비교가 공정하다.

프로그램 실행 결과의 다음 부분에 100회 실험 결과가 출력된다.

```text
Random Data
Number of Trials : 100
Selection Sort
Bubble Sort
Bubble Sort (Early Termination)
Insertion Sort
```

선택 정렬은 무작위 입력에서 비교 횟수가 거의 일정하다. 버블 정렬과 삽입 정렬은 입력의 역순 정도와 데이터의 배치에 따라 비교와 이동 횟수가 달라질 수 있다. 무작위 데이터에서는 세 알고리즘 모두 평균적으로 `O(n^2)` 수준의 큰 비용이 발생한다.

## 5. 입력 상태별 데이터 생성 방법

### 무작위 데이터

각 원소의 `key1`과 `key2`를 0부터 1,000,000 사이에서 독립적으로 생성하였다.

### 이미 정렬된 데이터

무작위 데이터를 준비한 뒤 `key1` 오름차순 및 원래 입력 순서를 보조 기준으로 사용하여 정렬하였다. 이후 이 데이터를 세 정렬 알고리즘의 동일한 입력으로 사용하였다. 시험 입력을 준비하는 정렬 과정은 측정에서 제외하였다.

### 역순 정렬 데이터

이미 정렬된 데이터의 순서를 뒤집어 `key1`이 내림차순이 되도록 만들었다.

### 일부 정렬된 데이터

먼저 `key1` 오름차순으로 정렬된 데이터를 만든 후, 전체 10,000개 중 500쌍의 위치를 무작위로 교환하였다. 즉, 전체 데이터 중 일부 원소에만 무작위 교란을 가하여 대부분의 순서가 유지되도록 하였다.

이 방법은 완전히 정렬된 데이터와 무작위 데이터의 중간 상태를 만들기 위한 것이다. 교란의 크기를 500쌍으로 고정했으므로 어느 정도 정렬된 입력이라는 조건을 명확하게 재현할 수 있다.

## 6. 입력 상태별 성능 분석

프로그램은 다음 네 가지 상태에 대해 비교 횟수와 이동 횟수를 출력한다.

- Random Data: 100회 평균 결과
- Sorted Data
- Reverse-Sorted Data
- Partially Sorted Data

### 이미 정렬된 데이터

선택 정렬은 매 위치마다 나머지 전체를 확인하므로 이미 정렬되어 있어도 비교 횟수가 크게 줄지 않는다. 다만 실제로 교환할 필요가 없으므로 데이터 이동 횟수는 매우 작거나 0에 가깝다.

일반 버블 정렬은 모든 순회를 수행하므로 정렬된 입력에서도 비교 횟수가 많이 발생한다. 반면 조기 종료 버블 정렬은 첫 번째 순회에서 교환이 발생하지 않는 것을 확인한 뒤 종료하므로 비교 횟수가 `n-1` 수준으로 크게 줄어든다.

삽입 정렬은 각 원소를 바로 앞의 정렬된 구간과 확인하지만 실제 이동이 거의 필요하지 않다. 따라서 비교와 이동 횟수가 모두 작아지며, 정렬된 입력에서 가장 효율적인 알고리즘 중 하나가 된다.

### 역순 정렬 데이터

역순 입력에서는 선택 정렬, 버블 정렬, 삽입 정렬 모두 많은 작업이 필요하다. 버블 정렬과 삽입 정렬은 거의 모든 인접 또는 앞쪽 데이터가 이동해야 하므로 이동 횟수가 크게 증가한다.

선택 정렬은 각 단계에서 최솟값을 찾아 한 번만 교환하므로, 비교 횟수는 크지만 이동 횟수는 버블 정렬과 삽입 정렬보다 상대적으로 적다.

조기 종료 버블 정렬은 역순 입력에서 거의 모든 순회에서 교환이 발생하므로 일반 버블 정렬과 비교 횟수 차이가 거의 없다. 조기 종료 조건은 교환이 없는 순회가 발생해야 효과가 있기 때문이다.

### 일부 정렬된 데이터

부분 정렬 데이터에서는 삽입 정렬이 이미 정렬된 부분을 활용하기 때문에 무작위 또는 역순 입력보다 훨씬 적은 이동으로 정렬할 수 있다. 조기 종료 버블 정렬도 데이터가 거의 정렬되어 있다면 교환이 없는 시점에 빠르게 종료할 수 있다.

선택 정렬은 입력이 어느 정도 정렬되어 있어도 최소값을 찾기 위한 전체 비교를 계속 수행하므로 비교 횟수 감소 효과가 작다.

## 7. 버블 정렬 조기 종료 효과

일반 버블 정렬은 한 번도 교환이 발생하지 않는 상태에서도 정해진 순회를 모두 수행한다. 조기 종료 버블 정렬은 교환 여부를 기록하는 `swapped` 변수를 사용하여 한 순회에서 교환이 없으면 즉시 종료한다.

따라서 다음과 같은 차이가 발생한다.

- 정렬된 데이터: 조기 종료 버블 정렬의 비교 횟수가 크게 감소
- 부분 정렬 데이터: 조기 종료 버블 정렬이 일반 버블 정렬보다 유리
- 무작위 데이터: 조기 종료 여부에 따른 차이가 상대적으로 작을 수 있음
- 역순 데이터: 대부분의 순회에서 교환이 발생하므로 차이가 작음

조기 종료 조건은 최악의 시간 복잡도를 바꾸지는 않지만, 입력이 이미 정렬되었거나 거의 정렬된 경우 실제 실행 시간을 크게 줄여준다.

## 8. 안정성 검증

안정성 검증을 위해 다음과 같이 `key1`이 중복되는 별도 데이터를 사용하였다.

```text
(527, 100, original_index=0)
(125, 300, original_index=1)
(527, 200, original_index=2)
(892, 400, original_index=3)
(125, 500, original_index=4)
(527, 600, original_index=5)
(125, 700, original_index=6)
(892, 800, original_index=7)
```

정렬 전후에 같은 `key1`을 가진 데이터들의 `original_index` 순서를 검사하였다. 같은 `key1` 그룹에서 원래 인덱스가 감소하면 상대 순서가 바뀐 것이므로 불안정 정렬로 판단하였다.

프로그램은 다음 네 가지 결과를 출력한다.

```text
Selection Sort       : ...
Bubble Sort          : ...
Insertion Sort (>)   : ...
Insertion Sort (>=)  : ...
```

### 선택 정렬

현재 구현은 최솟값을 찾은 뒤 선택된 원소를 현재 위치와 교환한다. 같은 `key1`을 가진 원소를 별도로 고려하지 않기 때문에, 최솟값 교환 과정에서 동일한 키를 가진 데이터의 순서가 바뀔 수 있다. 따라서 일반적인 선택 정렬은 안정 정렬이 아니다.

### 버블 정렬

버블 정렬은 앞의 `key1`이 뒤의 `key1`보다 클 때만 교환한다. 두 값이 같을 때는 교환하지 않으므로 동일한 키를 가진 데이터의 순서가 유지된다. 따라서 현재 구현의 버블 정렬은 안정 정렬이다.

### 삽입 정렬의 `>` 사용

삽입 정렬에서 다음 조건을 사용하면,

```c
while (j >= 0 && a[j].key1 > current.key1)
```

현재 값과 같은 `key1`을 가진 기존 데이터를 이동하지 않는다. 따라서 동일한 키의 상대 순서가 유지되며 안정 정렬이 된다.

### 삽입 정렬의 `>=` 사용

다음 조건을 사용하면,

```c
while (j >= 0 && a[j].key1 >= current.key1)
```

기존 데이터와 현재 데이터의 `key1`이 같아도 기존 데이터를 오른쪽으로 이동한다. 이 때문에 동일한 키를 가진 데이터의 상대 순서가 뒤집힐 수 있으며, 불안정 정렬이 된다.

즉, 삽입 정렬에서는 안정성을 유지하려면 `>`를 사용해야 하고, `>=`를 사용하면 동일 키 데이터까지 이동하여 안정성이 깨진다.

## 9. 알고리즘별 종합 비교

| 알고리즘 | 평균적인 시간 복잡도 | 정렬된 입력 | 역순 입력 | 안정성 |
|---|---|---|---|---|
| 선택 정렬 | `O(n^2)` | 비교 횟수 감소 작음 | 비교 횟수 동일 | 일반적으로 불안정 |
| 버블 정렬 | `O(n^2)` | 조기 종료 시 매우 유리 | 많은 비교·이동 | 안정적 |
| 삽입 정렬 | `O(n^2)` | 매우 유리 | 많은 비교·이동 | `>` 사용 시 안정적 |

선택 정렬은 데이터 이동 횟수가 상대적으로 적다는 장점이 있지만, 입력 상태와 관계없이 많은 비교를 수행한다. 버블 정렬은 인접 교환 때문에 역순 데이터에서 이동 횟수가 많지만, 조기 종료 조건을 추가하면 정렬된 데이터에서 성능이 크게 향상된다. 삽입 정렬은 정렬 상태를 가장 잘 활용하며, 정렬된 데이터나 부분 정렬 데이터에서 비교와 이동 횟수가 크게 줄어든다.

## 10. 결론

세 알고리즘은 모두 동일한 `key1` 기준 오름차순 정렬을 수행하지만, 입력 데이터의 초기 상태에 따라 성능 차이가 크게 나타난다.

- 선택 정렬은 입력 상태에 따른 비교 횟수 변화가 작고 이동 횟수가 비교적 적다.
- 일반 버블 정렬은 정렬된 입력에서도 불필요한 순회를 수행한다.
- 조기 종료 버블 정렬은 이미 정렬되었거나 거의 정렬된 입력에서 효과적이다.
- 삽입 정렬은 정렬된 데이터와 부분 정렬 데이터에서 가장 큰 이점을 얻는다.
- 역순 데이터에서는 버블 정렬과 삽입 정렬의 데이터 이동 횟수가 크게 증가한다.
- 안정성 측면에서는 버블 정렬과 `>`를 사용하는 삽입 정렬이 안정적이다.
- 선택 정렬은 단순한 교환 방식 때문에 일반적으로 안정적이지 않다.
- 삽입 정렬에서 `>`와 `>=`의 선택은 동일 키 데이터의 상대 순서를 보존하는지에 직접적인 영향을 준다.
