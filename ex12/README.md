# 과제 12: 퀵 정렬의 피벗 선택에 따른 성능 비교

## 1. 실험 목적

동일한 무작위 정수 데이터에 대해 퀵 정렬의 피벗 선택 방법을 달리하여 비교 횟수 차이를 측정하였다.

비교한 방법은 다음 세 가지이다.

- 첫 번째 원소 선택(First Element)
- 무작위 원소 선택(Random Pivot)
- 세 원소의 중앙값 선택(Median-of-Three)

데이터 크기는 1,000, 2,000, 4,000, 8,000, 16,000, 20,000으로 증가시켰다. 각 데이터 크기에서는 하나의 원본 배열을 생성하고, 동일한 복사본에 세 가지 퀵 정렬을 적용하였다.

---

## 2. 비교 횟수 기준

분할 과정에서 배열 원소와 피벗 값을 비교한 횟수를 측정하였다. 비교 결과와 관계없이 실제 데이터 값 비교는 1회로 계산하였다.

Median-of-Three에서는 첫 번째, 가운데, 마지막 원소의 중앙값을 결정하기 위한 비교도 포함하였다. 배열 인덱스 비교, 반복문 종료 조건, 무작위 위치 생성, 데이터 교환은 비교 횟수에서 제외하였다.

---

## 3. 구현 방법

### First Element

현재 정렬 구간의 첫 번째 원소를 피벗으로 선택한다. 구현은 간단하지만 입력이 이미 정렬되었거나 특정 패턴을 가지면 분할이 한쪽으로 치우칠 수 있다.

### Random Pivot

현재 정렬 구간에서 무작위 위치를 선택한다. 특정 입력 순서에 의한 최악의 분할 가능성을 줄이지만, 실행마다 피벗이 달라지므로 비교 횟수도 달라질 수 있다.

### Median-of-Three

현재 구간의 첫 번째, 가운데, 마지막 원소를 비교하여 세 값의 중앙값을 피벗으로 선택한다. 극단적인 값을 피하고 균형에 가까운 분할을 만들 가능성이 높다.

---

## 4. 실행 결과

이번 실행 결과는 다음과 같다.

| 데이터 크기 | First | Random | Median-of-Three |
|---:|---:|---:|---:|
| 1,000 | 12,154 | 10,955 | 11,299 |
| 2,000 | 24,350 | 24,165 | 24,385 |
| 4,000 | 54,033 | 53,662 | 55,428 |
| 8,000 | 122,163 | 120,051 | 116,266 |
| 16,000 | 254,708 | 271,363 | 253,485 |
| 20,000 | 363,699 | 346,866 | 346,935 |

모든 데이터 크기에서 정렬 결과는 `Sorted Check : PASS`로 확인되었다.

### 결과 분석

데이터 크기 1,000, 2,000, 4,000에서는 Random 방식이 가장 적은 비교 횟수를 기록했다. 데이터 크기 8,000과 16,000에서는 Median-of-Three가 가장 우수했으며, 20,000에서는 Random과 Median-of-Three가 거의 비슷한 결과를 보였다.

따라서 이번 실험에서는 특정 피벗 방식이 모든 데이터 크기에서 항상 가장 우수하지는 않았다. 무작위 데이터의 실제 분포와 각 분할에서 선택된 피벗에 따라 결과가 달라졌기 때문이다. 다만 Random과 Median-of-Three는 First 방식보다 큰 데이터에서 비교 횟수가 대체로 안정적이었다.

퀵 정렬은 분할이 균형적이면 평균적으로 `O(n log n)`의 성능을 보인다. 반대로 피벗이 최솟값이나 최댓값에 가까우면 한쪽 부분 배열만 커져 비교 횟수가 증가하고 최악의 경우 `O(n²)`에 가까워질 수 있다.

---

## 5. 보너스: 재귀적 퀵 정렬과 반복적 퀵 정렬

보너스에서는 데이터 크기 10,000, 피벗 방식 Median-of-Three 조건에서 재귀적 방식과 반복적 방식을 비교하였다. 반복적 방식은 명시적인 배열 스택을 사용하며, 재귀적 방식은 함수 호출 스택을 사용한다.

- 동일한 원본 데이터 사용
- 동일한 Median-of-Three 피벗 선택
- 동일한 분할 알고리즘 사용
- 데이터 복사 시간과 출력 시간은 측정에서 제외
- 20회 반복 후 평균 실행시간 계산

실행 결과:

```text
Data Size : 10000
Pivot     : Median-of-Three
Repeats   : 20

Recursive Quick Sort : 1.276200 ms
Iterative Quick Sort : 1.288600 ms
Sorted Check         : PASS
```

이번 측정에서는 재귀적 방식이 반복적 방식보다 약간 빠르게 나타났다. 그러나 차이는 매우 작으며, 실행 환경, 컴파일러 최적화, 시스템 부하에 따라 달라질 수 있다. 반복적 방식은 함수 호출 오버헤드를 줄일 수 있지만, 별도의 스택 배열에 구간을 저장하고 관리해야 한다. 재귀적 방식은 함수 호출이 발생하지만 코드 구조가 간단하고 퀵 정렬의 분할 구조를 직접적으로 표현할 수 있다.

두 방법은 동일한 피벗 선택과 분할 알고리즘을 사용하므로 정렬 결과는 같아야 한다. 실제로 두 결과 모두 `Sorted Check : PASS`로 확인되었다.

---

## 6. 결론

퀵 정렬의 성능은 피벗 선택에 따른 분할 균형에 큰 영향을 받는다. First 방식은 가장 단순하지만 입력 순서에 민감하다. Random 방식은 입력 편향을 줄이며, Median-of-Three는 일부 대표값을 이용하여 극단적인 피벗을 피한다.

이번 측정에서는 데이터 크기별로 가장 우수한 방식이 달랐다. 이는 무작위 데이터의 분포와 피벗 선택 결과가 매 실행마다 달라지기 때문이다. 따라서 하나의 실행 결과만으로 특정 방법이 항상 우수하다고 단정하기보다는 여러 번 실행하여 평균 비교 횟수를 확인하는 것이 더 정확하다.

보너스 비교에서는 재귀적 방식과 반복적 방식의 실행시간 차이가 크지 않았다. 재귀적 방식은 구현이 간결하고, 반복적 방식은 명시적인 스택을 사용하여 재귀 호출을 제거할 수 있다는 차이가 있다.
